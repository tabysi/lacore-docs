# Security & Admin

LACORE ships a hardened security stack and a staff toolkit. All of it runs on your own server.

![The LACORE security stack and the staff panel](/img/features/security-admin.svg)

## Anticheat

An **event-honeypot anticheat** guards server events against exploit tooling. The framework bridge
marks legitimate framework events (`Bridge.IsFrameworkEvent`) so they are never flagged as exploits.

## Permissions

Access is gated through ACE groups (`group.lacore_dev` / `lacore_staff` / `lacore_mod`) with an
optional **Discord role → ACE bridge**. Configure the bot token + guild convars and map roles to
groups; modules then check `HasPermission(src, perm)`. See [Discord & Duty](/configuration/discord).

## Bans

The connect flow validates bans safely (guarded against malformed entries and DB hiccups so a bad
record can never leave a player stuck on "Checking bans..."). Bans record who issued them, when, and
the reason.

Bans and warns live in `data/banlist.json`, and LACORE can carry over what txAdmin holds — see
[Ban List & txAdmin Import](/features/playerbase).

## Staff panel (`/admin`)

One window with three views on a rail — **1 Players · 2 Log · 3 Self** — and a selected player in
the aside that all three share. `/bblog` opens the same window on its log view.

### Access tiers

The panel shows what you may do rather than failing at the click. Tiers are derived from what you
already run — there is no new permission system:

| Tier | Who | May |
| --- | --- | --- |
| **Lead Dev** | the `dev` flag, or devmode | everything |
| **Admin** | the `staff` flag, or ACE `ban` | everything, including jail and ban |
| **Moderator** | ACE `kick` | the soft actions and kick, with a reason |

The tier is advisory: **every action re-checks on the server**, because a client can send any event
it likes. Kick, jail and ban additionally require a reason and a confirmation, and the reason is what
the log line and the Discord embed carry.

### Players

Search by name, character, id or department, filter by On duty / Civilian / Flagged, and see the
callsign, ping and the anticheat trust score per row. Selecting a player fills the aside: goto, bring,
spectate, freeze, unfreeze, revive, heal, mark on map — then kick, jail (via corrections) or ban.

### Activity log (Big Brother)

Everything `BBLog(category, src, action, detail, opts)` records: filter by category, player or free
text, page through it, or switch the feed **live**. Clicking a row opens that player's **dossier** —
their 30 days of activity with a per-category breakdown. Logs are written to `lacore_logs` and can be
mirrored to Discord webhooks (`lacore_bb_webhook*`).

> **Without a database** the log falls back to the memory buffer, and says so in the panel: searching,
> paging and dossiers are unavailable, while actions still write to the buffer and to Discord.

### Self tools

Noclip, god mode, invisible, heal self, repair vehicle and overhead server ids. All client-side, none
of it logged — it never leaves your own game.

Noclip and spectate clean up correctly on resource stop, so a restart mid-action can't leave a player
ghosted or stuck in spectator mode.

## Offline since 4.2.0

LACORE no longer talks to a LACORE service. The licence server and IP lock, the global ban network,
the shared playerbase and the telemetry reports were all shut down with the LACORE website, and
none of them protects or checks anything any more. No licence key is needed.

The only web requests LACORE makes go to addresses you configure yourself — see
[Nothing Leaves Your Server](/features/telemetry).
