# Ban List & txAdmin Import

LACORE keeps its bans and warns **on your server**, in `data/banlist.json` (warns carry
`type="Warning"`). They are written by `/ban` and `/warn`, and LACORE can pull in what txAdmin
holds, so the two lists do not drift apart.

<Callout type="info">
  **The shared LACORE playerbase was shut down in 4.2.0.** Uploading records, share keys with
  partner communities and the shared-ban check on connect (`lacore_playerbase_enforce`) depended on
  the LACORE website and no longer do anything; `/lacore bans upload` sends nothing. Your local bans
  and warns are unaffected.
</Callout>

## Your local list

From the server console:

```
/lacore bans list      # count your local bans + warns
/lacore bans import    # pull in txAdmin's bans and warns now
```

`list` counts what is in `data/banlist.json` and how many of those came from txAdmin. In the
**server console** (including txAdmin's live console) type the commands without the leading slash:
`lacore bans list`.

## If you ban from txAdmin

Most teams do — and txAdmin keeps its **own** database. `data/banlist.json` only ever held bans issued
with LACORE's `/ban` and `/warn`, so on a txAdmin server the LACORE list would hold a handful of
records while hundreds stayed in the panel.

**You do not have to do anything.** On every start LACORE looks for txAdmin's `playersDB.json` beside
your server and carries over what it finds — bans, warns, the lot. It runs at each boot rather than
once, which also covers bans issued in the panel while your server was down: those fire no event, so
without the sync they would never arrive.

Carrying over is safe to repeat. Records keep txAdmin's own action id, so a second pass adds nothing,
and bans an admin already lifted or that have run out are skipped rather than resurrected. The console
stays quiet unless something actually came across.

**New bans arrive as they happen.** `Integrations.txAdminBans` in `configs/cfg-integrations-sh.lua`
ships as `"auto"`, which mirrors every new txAdmin ban and warn the moment it is issued. Set it to
`false` to switch off both the mirroring and the boot sync.

<Callout type="info">
  Run `/lacore bans import` to do it on demand and see exactly what happened — which file was found,
  how many actions it holds, and what was skipped and why.
</Callout>

### Where it looks

A configured data path first, then txAdmin's own; then the artifacts folder, which is where txAdmin
puts `txData` by default; and finally the folders above the resource — plus the ones **beside** them.
That last part covers the common Linux split where the artifacts and the resources sit in separate
trees (`/home/FXServer/server` next to `/home/FXServer/server-data`), because walking straight up from
a resource in the second one never passes a `txData` at all.

**If it cannot find the file**, the command says how many paths it tried and lists the folders it
searched. Two things can put you here, and the list tells them apart: a layout nobody guessed (one line
will be your own path, off by a folder), or an FXServer build that gives resources no file access
outside their own folder — which the command names explicitly.

Point LACORE straight at it in `server.cfg`:

```cfg
setr lacore_txdata_path "/home/FXServer/server/txData"
```

That is the `txData` folder itself — the one holding `<profile>/data/`. The full path to
`playersDB.json` works too. `Integrations.txAdminDataPath` in `configs/cfg-integrations-sh.lua` does
the same; the convar wins if both are set. Restart the resource afterwards.

If file access is blocked outright, copy `txData/<profile>/data/playersDB.json` into the resource as
`data/txadmin-import.json` instead and run `/lacore bans import` — the command prints the exact path to
copy it to. Live mirroring is unaffected either way; it never touches the filesystem.

<Callout type="warning">
  txAdmin keeps **one database per profile**. If the sync reports *0 actions* while your panel shows
  bans, it found a different profile than the one your panel is looking at — a leftover dev profile on
  the same machine looks identical from the outside.
</Callout>

Mirroring and importing are **local bookkeeping** — nothing leaves your server. How bans are checked
when a player connects is on [Security & Admin](/features/security#bans).
