# [3.5.6] – 2026-09-11 — Housekeeping before the public release

A sweep for things that would embarrass a first-time buyer: one noisy default in the resource, and
two places in the customer portal where a choice was quietly thrown away.

<Callout type="warning">
**Config change:** `configs/config.lua` — `CallCenter.Debug` now ships as `false`. If you never
changed it, `/lacoreconfig restore` picks up the new default. If you want the 911/311 trace back in
your server console, set it to `true` yourself.
`configs/cfg-mdt-labels-sh.lua` changed in a comment only — no setting moved.
</Callout>

![Portal: ticket categories and the Config link](/img/changelog/portal-tickets-config-scope.svg)

### Fixed

#### The server console no longer traces every 911 call

`CallCenter.Debug` shipped as `true`, so a fresh install printed the full 911/311 call flow to the
server console on every call. It is a troubleshooting switch and is now off by default.

#### Support tickets keep the category you picked

**Dashboard → Support** offers eight categories, but the portal API only let four of them through.
*Installation & setup*, *Feature request*, *Report a player* and *Partnership* all reached the
Discord bot as **Other** — without the category's first-message hint, without the high priority a
player report opens at, and with the AI doc-assistant switched on for reports and partnerships that
are meant for a human. All eight now arrive as chosen.

#### A teammate with Config access can find the Config page

The sidebar showed **Config** only to team members holding the *Servers & license keys* scope, while
the page itself asks for the *Config* scope. Someone granted only *Config* had the access and no link
to it. The link now asks for the same scope as the page.

### Changed

- The whitelabel example in `cfg-mdt-labels-sh.lua` no longer names a real community — it reads
  `"Your Community MDT"`.

> **Not tested in-game or against the live portal.** The Lua files pass the syntax check,
> `landing/lib/api.mjs` passes `node --check` and the portal builds. Ticket routing was checked
> against the category list in the bot's `src/tickets.js`, not with a real ticket.
