# Player List

Press **I** to open the board: who is on duty, what they are doing, who else is online, and how the server itself is doing. It is a read-only overlay — the game keeps running underneath and your mouse stays in the world, so you can open it mid-scene without losing control of your character.

There are **two styles**, and your server owner picks one in `configs/cfg-hud-sh.lua`:

| Style | What you get |
|-------|--------------|
| **`"duty"`** *(default)* | The full-screen duty board — units grouped by department, a civilian roster, area of play and server state. Everything on this page. |
| **`"minimal"`** | A compact centred card: server ID, account name, character name, ping, and department plus callsign for anyone on duty. Jump to [Minimal style](#-minimal-style). |

Both read the same data and use the same keys.

> 📑 **Related:** [Keybinds](/getting-started/keybinds) · [Using the MDT](/user-guide/mdt) · [Dispatch Console](/user-guide/dispatch-console)

## 🗺 The header

```
┌────────────────────────────────────────────────────────────────────────────┐
│ LACORE ROLEPLAY                    ONLINE  ON DUTY  AVAILABLE  LOCAL TIME  │
│ SANDY SHORES                           64       26         11      21:47   │
│ Area of play · unchanged 42 min                                            │
│ ────────────────────────────────────────────────────────────────────────── │
│ ⚑ ALERT  Pursuit policy in effect.      ● 911 dispatch · 2 on duty │ All … │
└────────────────────────────────────────────────────────────────────────────┘
```

The big line is the **area of play** and how long it has been unchanged. Above it is your community name, which comes from `configs/cfg-branding-sh.lua` — it is your name, not ours.

**Available** counts the units whose status is **CLEAR** — the ones who could take a call right now. It is deliberately a separate number from *on duty*: twenty-six on shift with two clear is a very different server than twenty-six with twenty clear.

The strip below carries the three things worth knowing before you commit to a scene: the current **server alert**, whether **911 dispatch is staffed**, and whether the server is open to everyone, members-only, or currently running **without emergency services**.

## 🚓 Units, by department

The left half is the duty board. Units are grouped by their department, and **never paged** — the whole point of the board is to answer "who is on duty right now", and an answer split across pages is not one.

```
┃ LSPD  9 on duty  4 available ───────
┃ 12  1-L-30     Michael Adams      CLEAR      22
┃                Tabysi
┃ 17  1-ADAM-12  Sarah Reed         ON SCENE   41
┃                SomePlayer
```

Every department header carries **how many of its units are available** next to the on-duty total — the same CLEAR rule as the header. A department with nobody clear shows its `0 available` in red instead of green, because that is the state you want to notice, not the one you want hidden.

| Column | What it means |
|--------|---------------|
| **ID** | Their **server ID** — the number every admin command takes. Units are addressed by callsign in character, but the ID is what you need out of it. |
| **Callsign** | Their unit callsign. `—` if they are on duty without one. |
| **Name** | Their **character name** on top, account name underneath. |
| **Status** | Duty status in the same colours the MDT uses — CLEAR, ENROUTE, ON SCENE, BUSY, … |
| **Ping** | Green under 60 ms, amber under 120 ms, red above. `—` means it is not known yet. |

The **left edge of each row carries the status colour**, so a department that has gone quiet or one that is all lit up reads before you have read a single word. A unit with no status yet shows its department's colour instead.

**Department colours come from the department name**, so LSPD is the same blue on every player's screen, and it does not change when another department goes off duty. Well-known agency names (LSPD/LAPD, sheriff/BCSO, AMR/EMS/fire) keep their traditional colours; anything you have named yourself gets its own stable colour. The same colours are used in the radio log.

## 👥 The civilian roster

The right half is everyone not on duty, two dense columns, sorted by server ID.

```
  12 ● Michael Adams   Tabysi        22     31 ● Elena Cruz    Someone      58
  17 ● Sarah Reed      SomePlayer    45     36 ● Marcus Hale   Spawn …     141
```

Each row is **server ID · role · account name · character name · ping**. The two names share the row evenly, so a long Steam name can never push the character name off it.

The dot is the player's **role** — Staff, Dev, Supporter, Donator, Member — with the legend along the bottom. Players in a **different session** than you are dimmed, and you are highlighted.

This is the half the **arrow keys page**, and only when there is more than one page.

> ℹ️ **Why some players show no character name.** Someone still in the spawn or freeroam session has not picked a character yet, so the board shows the session instead. That is not an error.

## 📄 Minimal style

If your owner set `playerlistStyle = "minimal"`, the board is a single centred card instead:

```
┌──────────────────────────────────────────────────────┐
│ LACORE ROLEPLAY 64 17 on duty 8 available  SANDY … 21:47│
│ ──────────────────────────────────────────────────── │
│ │  1  Tabysi ●     Michael Adams  LSPD · 1-L-30  CLEAR  22 │
│ │  2  SomePlayer   Sarah Reed        AMR · M-1  ON SCENE  41 │
│ │  3  Randomer     Spawn session                        141 │
│ ──────────────────────────────────────────────────── │
│ Page 1 of 3                              ← → to page │
└──────────────────────────────────────────────────────┘
```

Everyone is in one list sorted by server ID — no split, no department grouping. Every row carries the **server ID, the account name and the character name**, on duty or not: the department and callsign next to a unit say which callsign is talking, not who is playing it. Someone who has not picked a character yet shows which session they are in instead. Players on duty additionally show their department and callsign with their status colour. The dot after a name is their role, and the header still carries the player count, how many are on duty, how many of those are available, the area of play and the clock.

The arrow keys page this list, and because it is one list rather than two, **the page covers everybody** — units included.

## ▭ Bar style

`playerlistStyle = "bar"` draws the same roster as a strip across the **top** of the screen — full
width, three rows deep:

```
╔══════════════════════════════════════════════════════════════════════════════╗
║ LACORE ROLEPLAY  74   5 on duty  1 available            LOS SANTOS  21:14  1/3 ║
║ 1 Tabysi  Michael Adams 1-L-30 22 │ 4 Randomer  Spawn session      141 │ …    ║
║ 2 Player2 Sarah Reed      M-1  41 │ 5 Someone   Chris Vale          38 │ …    ║
║ 3 Player3 Dana Ruiz     1-A-12 30 │ 6 Another   Jo Kim              55 │ …    ║
╚══════════════════════════════════════════════════════════════════════════════╝
```

It covers roughly a seventh of the screen instead of the middle of it, which suits players who keep
the list open during a scene rather than glancing at it. Each **column reads top to bottom**, columns
run left to right, and a page holds 27 players. On-duty players carry their callsign in its status
colour; the role stripe, ping colours and the dimming of players in another session work exactly as
on the other boards.

## ⌨️ Controls

| Key | Action |
|-----|--------|
| **I** | Open / close the board |
| **←** / **→** | Previous / next page — the civilian roster on the duty board, the whole list on the minimal card and the bar |

There is nothing to click: the board takes no cursor, so it can never trap your mouse in the UI. Names above heads are shown while it is open, as before.

## 🛠 For server owners

The board is part of the HUD and follows the HUD config (`configs/cfg-hud-sh.lua`):

```lua
HudCfg = {
    enabled    = true,   -- master switch for the whole HUD
    playerlist = true,   -- the "I" board
    playerlistStyle = "duty",   -- "duty" | "minimal" | "bar"
    nameplates = true,   -- names above heads while the board is open
}
```

Turning `playerlist` off leaves the key registered but the board never opens.

`playerlistStyle` picks the **default** board — `"duty"`, `"minimal"` or `"bar"`. Players can choose their own under **Settings ▸ Player Location Display ▸ Player List Style**; that setting ships on *Server default*, which means "whatever this config says". Anything else is reported once in the server console and falls back to `"duty"` — a typo should not quietly look like a setting that does nothing. The duty board sends different data from the other two (it sends units in full and pages only civilians, while `minimal` and `bar` page the whole roster as one list), so each ships exactly the rows it draws. `minimal` and `bar` share that flat payload and differ only in how many players fit on a page: 24 and 27.

**Ping is read on the server**, not on each client — with OneSync a client only sees players inside its own scope, so a client-side reading would be blank for everyone across the map.

Roles come from the Discord role mapping (see [Discord configuration](/configuration/discord)); a player with no role simply has no dot colour of their own.

The area of play disappears from the header when the AOP feature is switched off; the board then says so rather than leaving a gap.
