# Permissions & ACE

Everything LACORE checks before it lets someone ban a player, restore a config, write a personnel
file or bypass the anticheat runs through one helper — `HasPermission(src, "<key>")`. This page is
about the file that decides what that helper says: **`configs/cfg-permissions-sv.lua`**.

<Callout type="info">
  **Start here: `/lacoreperms`.** Run it in the server console (or in game, if you hold `lacore`) and
  it prints every permission LACORE knows, whether you hold it, and the `add_ace` line to grant it.
  You should rarely need to read this page instead of that command.
</Callout>

## How a permission is answered

In order — the first hit wins:

1. **The server console** (id 0) and **devmode** always pass.
2. A **Discord Staff / Dev flag** passes everything, as far as `bypass` allows it.
3. **ACE**: `lacore.<key>`, then `command.<key>`, then the blanket `lacore`, then the bare `<key>`
   (that last one only while `acceptBareAce` is true).

A key that already begins with `lacore.` is not prefixed a second time, so `lacore.ac.bypass` is
looked up exactly as written.

## The Discord → ACE bridge

FiveM checks restricted commands (`/ban`, `/kick`, `/dc` …) against ACE **itself**, before any Lua
runs. Holding the Discord "Staff" role is therefore not enough on its own — the player has to *be*
something in ACE. LACORE bridges that for you: on connect their identifier goes into the group that
matches their flag, and it comes back out when they leave **or lose the role**.

```lua
roleGroups = {
    { flag = "dev",   group = "lacore_dev"   },
    { flag = "staff", group = "lacore_staff" },
    -- { flag = "mod", group = "lacore_mod" },
},
```

Set `bridge = false` to switch the whole mechanism off and manage principals yourself in
`server.cfg`. It also switches itself off when `AccessControl.discordRoles` is `false` — with no
Discord roles there are no flags to bridge.

## The blanket bypass

```lua
bypass = {
    dev   = true,
    staff = true,
},
```

A player carrying that Discord flag passes **every** check, whatever ACE says.

<Callout type="warning">
  `staff = true` means anyone with the Staff role can also restore configs and run the owner
  commands — those are gated by `lacore`, and the bypass clears it. Set it to `false` to hold Staff
  to the rights their group actually has, and grant the extras explicitly.
</Callout>

## The groups

Three ship by default. Add your own freely — they are created at start-up exactly as listed.

| Group | Holds |
| --- | --- |
| `group.lacore_dev` | Every restricted command, the blanket `lacore` right, inherits staff |
| `group.lacore_staff` | kick, ban, tempban, unban, warn, staff, dc, screen + staffchat / noclip / tp / revive, inherits mod |
| `group.lacore_mod` | kick, tempban, warn, staff |

```lua
groups = {
    lacore_staff = {
        commands = { "kick", "ban", "tempban", "unban", "warn", "staff", "dc", "screen" },
        aces     = { "timeout", "lacore.staffchat", "lacore.noclip", "lacore.tp", "lacore.revive" },
        inherits = "lacore_mod",
    },
},
```

`commands` become `command.<x>`, `aces` are plain ACE objects, `allCommands = true` is shorthand for
the blanket `command` ACE, and `inherits` pulls in another group's rights.

## Granting rights yourself

```
add_principal identifier.discord:000000000000000000 group.lacore_staff
add_ace group.lacore_staff lacore.admin allow
```

The principal can be any identifier (`discord:`, `license:`, `fivem:`, `steam:`). Run
`/lacoreperms` for the exact line for each permission.

## Bare ACE names

```lua
acceptBareAce = true,
```

LACORE has always accepted a bare object name (`admin`) alongside the prefixed one
(`lacore.admin`), and it is left on so an update never takes rights away. But a generic word can
collide with another resource that happens to use it — anyone holding some other script's `admin`
ACE would reach LACORE's replay recorder and asset library through it. Once your `server.cfg` uses
the `lacore.` names, set this to `false` and the collision is gone.

## What LACORE asks for

| Key | ACE | In the box |
| --- | --- | --- |
| `lacore` | `lacore` | Blanket: every `lacore.*` right, owner commands, config restore |
| `ban` / `unban` | `command.ban` | Ban a player, and counts as admin in the report panel |
| `kick` | `command.kick` | Kick a player, and counts as moderator |
| `tempban` / `warn` / `staff` | `command.<x>` | The matching moderation commands |
| `dc` / `screen` | `command.<x>` | Disconnect / screenshot a player |
| `timeout` | `timeout` | Exempt from the connection timeout check |
| `admin` | `lacore.admin` | Replay recorder, preview capture, asset library, stream budget |
| `nads` | `lacore.nads` | NADS terminal |
| `lacore.supervisor` | `lacore.supervisor` | Supervisor panel — see [Supervisor Panel](/configuration/supervisor) |
| `personnel.write` | `lacore.personnel.write` | Write personnel records |
| `lacore.ac.bypass` | `lacore.ac.bypass` | Anticheat whitelist — see [Anticheat & Security](/configuration/security) |
| `lacore.staffchat` / `.noclip` / `.tp` / `.revive` | same | Staff channel, noclip, teleport, revive |

The vehicle spawner's key is whatever you set in `VehicleSpawner.permission`
(`configs/cfg-server-sv.lua`); `/lacoreperms` lists it under that name.

## Commands

| Command | What it does |
| --- | --- |
| `/lacoreperms` | Every permission, who holds it, and ready-made `add_ace` lines. Needs `lacore` (or the console). |
| `/myperms` | The calling player's own group, flags and a couple of resolved checks. |

## Related gates

Not everything goes through `HasPermission` — three other gates decide their own questions, and each
can *also* be satisfied by an ACE:

- **[Agency duty access](/configuration/discord)** (`DutyAccess`) — which agency a unit may go on duty for.
- **[Supervisor panel](/configuration/supervisor)** (`SupervisorConfig`) — framework grade, ACE, Discord role or allowlist.
- **Dispatcher** — whoever has the dispatch console open; also what the Zone Editor checks.
