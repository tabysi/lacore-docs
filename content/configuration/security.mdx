# Anticheat & Security

## Anticheat — `configs/cfg-anticheat-sh.lua`

<Callout type="info">
  **Ships enabled, in observe mode.** `Anticheat.Enabled = true` + `Mode = "observe"` by default:
  every check runs and logs what it *would* have done, but nothing is kicked or banned. That is safe
  to run untouched from day one. Run observe for a week, watch the log — when it stops surprising
  you, switch `Mode` to `"enforce"`.
</Callout>

Per-detection action (in observe mode, all four behave as `"log"`):

| Action | Effect |
| --- | --- |
| `"log"` | Discord webhook (`Webhooks.AdminLog`) only. |
| `"trust"` | Webhook + trust points — escalates to kick/ban only if the player keeps at it. |
| `"kick"` | Webhook + kick. |
| `"ban"` | Webhook + permanent ban (via `BanPlayer`). |

Bypass: `lacore_devmode = true` disables it entirely; players with the `Staff` / `Dev` Discord role, or
the `lacore.ac.bypass` ACE permission (`Anticheat.Whitelist`), are never punished (only logged).

```lua
Anticheat = {
    Enabled = true,       -- ships ON …
    Mode    = "observe",  -- … but in observe mode: log-only until you switch to "enforce"

    -- Server-side checks
    Explosions   = { action = "ban" },
    WeaponDamage = { action = "kick" },
    EntitySpam   = { action = "kick", skipOnFramework = true },  -- ESX/QBCore garages spawn server-side

    -- Client-side detections (bypassable, so default actions are milder)
    GodMode            = { enabled = true, action = "kick" },
    BlacklistedWeapons = { enabled = true, action = "ban" },
    -- … excerpt only — the file also carries SpeedHack, Teleport, NoClip, Invisible, SuperJump,
    -- BlacklistedVehicles, AntiDump, Honeypots, EventRateLimit, the Trust escalation model and the
    -- server-authoritative ServerSweep + Combat checks.
}
```

<Callout type="warning">
  The **thresholds, honeypot names and blacklists are not in this file** — they live in the escrowed
  `modules/anticheat/` so cheaters can't read the exact numbers to stay under. Anything you set in
  `cfg-anticheat-sh.lua` overrides the shipped default; whatever you leave out keeps the default.
  See [Anti-Cheat & Security](/anticheat) for the full feature overview and the recommended
  `server.cfg` hardening block.
</Callout>

## Member-only vehicles — `configs/cfg-blacklist-sh.lua`

Vehicle **classes** and specific **models** only "members" may drive:

```lua
memberOnlyVehicles = {
    18, 16, 15, 19, 7, 22,   -- vehicle CLASSES (see FiveM vehicle class list)
    -- specific models:
    "kosatka", "technical", "terbyte",   -- armoured / armed
    "bestiagts", "corsita",              -- rare / expensive
    "monster", "rcbandito",              -- abuse-prone niche
    -- …
}
```

Add class **numbers** or model **name strings**. Who counts as a "member" is set by
`AccessControl.membership` in [`cfg-server-sv.lua`](/configuration/discord) — `"auto"` / `"open"` / `"role"`,
driven by the Discord **Member** role, not by playtime. (`ProfileConfig.membershipHours` only decides when
the "you've played enough to apply for membership" notice fires — it does **not** unlock these vehicles.)

## Dashboard remote config and identity link — shut down

> ℹ️ Shut down in 4.2.0. LACORE runs fully offline, so there is no dashboard that can push config to
> your server and nothing is sent to a LACORE ingest service. `configs/cfg-remoteconfig-sh.lua` and
> `configs/cfg-identitylink-sh.lua` have no effect any more; you can leave them as they are. A config
> file the old dashboard cached on your server is covered under
> [Setup review](/configuration/autoconfig#leftover-dashboard-config).

## Big Brother (admin logging) — `configs/cfg-bigbrother-sv.lua`

Server-only. Every important event flows through `BBLog()` into a searchable DB table and optionally
to Discord. Viewed in-game via `/bblog` (role-gated).

```lua
BigBrother = {
    enabled     = true,
    accessRoles = { "Staff", "Dev", "LeadDeveloper" },   -- who may open /bblog
    retentionDays = 30,     -- logs older than this are pruned on start + daily
    flushSeconds  = 5,      -- buffered writes flush interval …
    maxBuffer     = 250,    -- … or when the buffer exceeds this

    categories = {          -- toggle whole categories on/off
        connection = true,  -- join/leave, identifiers, session length
        combat     = true,  -- kills / deaths
        admin      = true,  -- kick/ban/jail/warn
        anticheat  = true,  -- anticheat flags
        chat       = true,
        command    = true,
        vehicle    = true,  -- spawns / deletes
        mdt        = true,  -- MDT / dispatch actions
    },
}
```

Discord mirroring uses the `lacore_bb_webhook*` convars — see
[Server Convars](/configuration/convars#big-brother-admin-logging).

### Nothing leaves your server

Big Brother logs only to your own database and to the Discord webhooks you set. Up to 4.1.0 every line
was also copied to the LACORE dashboard; since 4.2.0 nothing is sent there. The `dashboard.batchSeconds`
and `dashboard.maxBatch` settings in the file no longer do anything.

## Discord Rich Presence — `configs/cfg-presence-sh.lua`

Controls the Discord status players see while playing and the invite link on the connect screen.
Requires a Discord Application (Developer Portal → New Application) for the `appId` and uploaded art
assets. The `Discord`/`Website` buttons appear in the player's Discord profile — great for organic
recruiting. Both the invite and website fall back to the `lacore_discord_invite` / `lacore_website`
convars when left blank.
