# CAD Terminals & Routing

LACORE ships several CAD/MDT terminals. They are **re-skins of one system**: one call list, one unit
list, one set of incidents, one dispatch. An officer in the Sheriff CAD and one in the Agency MDT are
looking at the same data in different clothes.

This page is about *which* terminal a department gets, and the config files around it. For how to
actually use a terminal, see the [User Guide](/user-guide/mdt).

| Terminal | `cad` value | Look |
| --- | --- | --- |
| LACORE Mobile Client (LAPD PremierOne) | `"lapd"` | Green-on-navy in-car terminal |
| CAD / PCMS (Sheriff) | `"lasd"` | Amber / teal |
| Agency MDT | `"agency"` | CHP-style dark blue |
| EMS / Fire CAD | `"ems"` | Dark medical CAD |
| 9100-T Terminal | `"90s"` (`"retro"` is accepted as an alias) | Green-phosphor 90s CRT |
| Pennsylvania CAD | `"penn"` | Retro county terminal (add-on) |
| Spillman Flex Mobile | `"spillman"` (`"flex"` is accepted as an alias) | Flex-style mobile CAD: message center, call screen with map |

Each one can be switched off individually in [`cfg-features-sh.lua`](/configuration/features) under
`cad`.

## MDT Desktop — `configs/cfg-mdtos-sh.lua`

`/mdt` boots a computer first: a POST screen, a sign-in screen, then a desktop with the
department's CAD as an app on it — see the [MDT Desktop](/user-guide/mdt-desktop) guide. It sits in
front of **every** terminal below and changes nothing about which one a department gets.

![What /mdt does: boot, sign in, desktop, CAD](/img/mdt/mdt-desktop-flow.svg)

Boot and sign-in run once per shift; every later `/mdt` resumes from standby. Switch the whole
thing off with `cad.os = false` in [`cfg-features-sh.lua`](/configuration/features) and the
terminals open directly again.

| Setting | Default | Description |
| --- | --- | --- |
| `name` | `""` | Name on the boot screen and in the Start menu. Empty uses the community name from `cfg-branding-sh.lua`. |
| `bootSeconds` | `4.5` | Length of the boot screen. `0` skips straight to the sign-in. |
| `loginSeconds` | `2.0` | The "Welcome" animation after **Sign in**. |
| `resumeSeconds` | `0.9` | The resume-from-standby fade every later `/mdt` uses. |
| `wallpaper` | `"auto"` | `"auto"` paints the department colours; a path under `nui/` or an `https://` URL uses that image. |
| `systemApps` | `true` | Notes, Settings, Clock and the intranet page on the desktop. |
| `decoIcons` | `true` | The decorative Recycle Bin and intranet shortcut. |
| `machineName` | `"auto"` | Machine name on the sign-in screen and the taskbar. `"auto"` builds one from the callsign (`MDT-1L30`). |

The sign-in is an animation, not a password check — LACORE has no per-player computer password on
the server, and a prompt that accepts everything would only look like security.

## Choosing a terminal per agency

Set `cad` on the agency in [`config.lua`](/configuration/main#choosing-the-cad-design):

```lua
{
  type  = "Law Enforcement",
  short = "VSPD",
  long  = "Vespucci Police Department",
  cad   = "lasd",          -- this department opens the Sheriff CAD
}
```

That is the whole setting. Every faction on your server can pick its own terminal, and two
departments may share one.

## Terminal routing

When a player runs `/mdt` (default key **O**), LACORE walks this list top to bottom and opens the
first terminal that matches:

1. **The agency's own `cad` field** — if the agency has one and that terminal is available here.
2. **Pennsylvania CAD** — the department name contains one of `Penn.deptTags`, and the add-on is
   unlocked.
3. **Spillman Flex Mobile** — the department name contains one of `Spillman.deptTags`, and
   `cad.spillman` is on.
4. **9100-T** — the department name contains `90s`.
5. **Sheriff CAD** — the department name contains `lasd`, `sheriff` or `bcso`.
6. **EMS / Fire CAD** — the *job* is Fire/EMS, AMR or Coroner, or the department name contains
   `fire`, `ems`, `fd`, `medic` or `amr`.
7. **Agency MDT** — any other law-enforcement department.
8. **LACORE Mobile Client** — the department name contains `lapd`.

If none match, no terminal opens and the player is told they have no agency.

<Callout type="info">
  Steps 2–7 are the name guess LACORE has always used. Step 1 is the way to stop guessing: a
  department that names its terminal is routed by that name and nothing else.
</Callout>

Two things happen before any of this:

- **Job gate** — only Law Enforcement, Fire/EMS, AMR and Coroner can open a terminal at all
  (`devmode` bypasses it).
- **Vehicle gate** — `MdtConfig.requireVehicle`, below.

### When a chosen terminal isn't available

If an agency asks for a terminal that is switched off in `cfg-features-sh.lua`, whose module isn't
loaded, or which is a locked add-on, that choice is skipped and the name guess applies instead. A
department never ends up with no terminal because of a setting elsewhere.

A `cad` value that isn't one of the six above is reported once in the server console
(`cad = "..." is not a terminal`) and then ignored.

## MDT options — `configs/cfg-mdt-sh.lua`

Applies to every terminal.

| Setting | Default | Description |
| --- | --- | --- |
| `requireVehicle` | `false` | Only allow *opening* a terminal while inside a vehicle (any seat). An already-open terminal still closes on foot, so nobody gets stuck. `devmode` bypasses. |
| `closeOnExit` | `false` | Auto-close the open terminal the moment the officer steps out of the car. Pairs with `requireVehicle`. `devmode` bypasses. |
| `announceRuns` | `true` | Broadcast `"<callsign> ran <query>"` in chat to on-duty units whenever someone runs a person or a plate. Set `false` for silent lookups. |

## Renaming terminal labels

Every label in every terminal can be renamed in `configs/cfg-mdt-labels-sh.lua` — see
[whitelabelling](/features/mdt-and-dispatch). Useful when your server's factions aren't called LAPD
and LASD.

## Pennsylvania CAD — `configs/cfg-penn-sh.lua`

A retro county terminal for the same dispatch data. Unlocked as an add-on
(`Features.penncad`); on a server without it, departments tagged for it fall back to the terminal
they had before.

| Setting | Default | Description |
| --- | --- | --- |
| `deptTags` | `{ "pennsylvania", "penn cad", "mobilecom" }` | Department-name substrings that route a player here. Lowercase, matched as a substring — `"pennsylvania"` also matches "Pennsylvania State Police". |
| `callPrefix` | `""` | Cosmetic prefix in front of the call number (`"P26"` → `P261042`). Display only; the real incident number is unchanged everywhere else. |
| `plateLabel` | `"SA Plate"` | Label on the plate button in the command bar. |
| `callTypes` | 16 entries | The "Create a Call" tile grid — the call types a unit can raise from the terminal. One tile each, in this order. |
| `dispositions` | 12 entries | Disposition codes offered when clearing a call (**F11 → Dispositions**). `code` goes into the incident log, `label` is what the unit reads. |

Setting `cad = "penn"` on an agency is the direct alternative to naming the department after a tag.

## Spillman Flex Mobile — `configs/cfg-spillman-sh.lua`

A Flex-style mobile terminal for the same dispatch data: message center, call screen with the live
map and status keys down the left, name/vehicle searches and the name record. Part of the core —
switch it off with `cad.spillman = false` in [`cfg-features-sh.lua`](/configuration/features).

![Spillman Flex Mobile call screen layout](/img/mdt/spillman-flex-layout.svg)

| Setting | Default | Description |
| --- | --- | --- |
| `deptTags` | `{ "spillman", "flex" }` | Department-name substrings that route a player here. Lowercase, matched as plain text. |
| `callPrefix` | `""` | Cosmetic prefix in front of the call number (`"26-"` → `26-1042`). Display only. |
| `stateCode` | `"SA"` | State shown in plate and licence returns (`LIS/SA`). |
| `statusKeys` | 10 keys, F2–F11 | The status keys down the left of the call screen. Each is `{ code, key, status }` (sets a LACORE status) or `{ code, key, action }` with `action` = `"assign"`, `"ack"` or `"resolve"`. `code` is only the label. |
| `dispositions` | 10 entries | Disposition codes offered when completing a call (**CMPLT**). |

`status` must be one of LACORE's unit statuses — `CLEAR`, `ENROUTE`, `ON SCENE`, `CODE SIX`, `BUSY`,
`UNAVAILABLE`, `OUT TO STATION`. Only `CLEAR` detaches the unit from its call.

Setting `cad = "spillman"` on an agency is the direct alternative to naming the department after a
tag.

## In-car screen — `configs/cfg-vehiclescreen-sh.lua`

Paints the CAD onto the dashboard screen of a police vehicle while you drive. Display only — the MDT
key still opens the full terminal.

<Callout type="warning">
  This needs support from the **vehicle model**: a render target (`script_rt_*`) or a texture only the
  screen uses. A script cannot add one. Run `/lacore screen target` and `/lacore screen dui` once per
  model to find out which your vehicle supports.
</Callout>

| Setting | Default | Description |
| --- | --- | --- |
| `enabled` | `true` | Master switch. |
| `audience` | `"leo"` | Who sees a screen: `"leo"` (LEO on duty), `"duty"` (anyone on duty), `"all"` (everyone, mostly for testing). Drawn per client, so a civilian passenger sees the model's own texture. |
| `view` | `"mdt"` | `"mdt"` = the full Mobile Client filling the screen. `"incar"` = a stripped dashboard terminal (active incident, calls, units, status dock) — fewer things, larger. (`"compact"` is the old spelling of `"incar"`.) |
| `width` / `height` | `864` / `1450` | Browser size behind the screen. Give this the **shape** of the screen in the model, not just a size — the texture is stretched onto whatever quad the modder built. Also the main cost of the feature. |
| `zoom` | `nil` | `nil` = automatic. A number overrides it: `1` = the raw terminal, `2` = twice the size and half the content on screen. Zoom trades rows in the call list for legibility. Only affects `view = "mdt"`. |
| `brightness` | `0.6` | How bright the terminal is drawn, `0.05`–`1`. Your screen probably glows, and that is the *model*: render targets are instrument clusters, which are built self-illuminated and run through bloom. Nothing in a resource reaches that — but the game multiplies, so halving what is drawn roughly halves the glow. `1.0` turns it off. |
| `tickMs` | `1000` | Redraw interval in ms when nothing changed. Data arrives by push, so this only covers the clock and the "time since dispatched" counters. |
| `models` | one entry | Per-model setup: `renderTarget` (the `script_rt_*` name the model declares, preferred) and/or `txd` + `texture` (the replacement route), plus a `cam` position. Give both where you have both. |
| `passengers` | `true` | Draw the screen for passengers too — the two-officer unit is what the in-car terminal is best at. Each occupant gets their **own** terminal, signed in as themselves. ⚠ One browser per occupied seat, not per car: the one setting here with a real cost. |
| `sharedCursor` | `true` | Show each other's mouse pointer while more than one of you works the screen. Pointers only — clicks are deliberately not shared, or the driver would self-assign to whatever the passenger tapped. |
| `focusCommand` | `"cad"` | Command that leans the camera in and hands you the mouse. Run again (or press Escape) to lean back out. Rename it on a clash, or `false` to register none — the "LACORE: Focus the in-car screen" key binding still works. |
| `focusMs` | `900` | Length of the camera move, each way, in ms. |
| `cursorRect` | measured | Where the screen ends up on your monitor, normalised. This is what the mouse is mapped through — outside it no click is sent at all, which is almost always why a terminal "does not react". Set it with `/cad adjust`. |

See also the [in-car screen user guide](/user-guide/in-car-screen).
