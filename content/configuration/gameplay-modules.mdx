# Gameplay & Misc Modules

The smaller, self-contained config files — one per feature. Each is escrow-open and carries a comment
header in the file itself; this page is the quick reference. Toggle any of these off entirely in
[Feature Toggles](/configuration/features).

## Air Unit — `configs/cfg-airunit-sh.lua`

The helicopter observation camera (heli-cam) for LEO air support: orbit a target, zoom, switch vision
modes and drop a spotlight.

```lua
AirUnit.enabled = true
AirUnit.jobs    = { "Law Enforcement" }   -- jobs allowed to use the heli-cam

AirUnit.orbit = { radius = 150.0, altitude = 120.0, speed = 20.0 }  -- auto-orbit around the locked target
AirUnit.cam = {
  fovMax = 70.0, fovMin = 8.0,   -- zoom range (wide … tight)
  fovSpeed = 5.0, panSpeed = 6.0, -- zoom + gimbal pan/tilt speed
  scanTime = 2.5,                 -- seconds the crosshair must hold an entity to lock it
  modes = { "normal", "night", "thermal" },
}
AirUnit.spotlight = { range = 300.0, brightness = 25.0, radius = 12.0 }
```

<Callout type="info">
  The overlay can show live **street names / directions** under the crosshair
  (`AirUnit.cam.streetNames` / `AirUnit.cam.streetDirections`, tuned with `AirUnit.cam.overlayGrid` and
  `AirUnit.cam.overlaySpacing`), sampled on a grid around the aim point.
</Callout>

## Corrections / Jail — `configs/cfg-corrections-sh.lua`

Server-authoritative jail. An arrest with jail time books the suspect automatically (see the penal
code), and the sentence persists across reconnects.

| Setting | Default | Meaning |
| --- | --- | --- |
| `Corrections.enabled` | `true` | Master switch for the jail / corrections system. |
| `Corrections.secondsPerMonth` | `30` | Real seconds served per sentenced "month". |
| `Corrections.minSeconds` / `maxSeconds` | `30` / `1200` | Clamp on any single sentence. |
| `Corrections.autoBookArrests` | `true` | An arrest report with jail time books the suspect automatically. |
| `Corrections.persist` | `true` | Keep the remaining sentence across reconnects. |
| `Corrections.jailCoords` / `releaseCoords` | — | Where inmates are held / released. Move these to your map. |
| `Corrections.jailRadius` | `150.0` | How far an inmate may move from `jailCoords` before being teleported back — size it to cover a custom prison's grounds (inside the game's JAIL zone it doesn't apply). |

## Impound — `configs/cfg-impound-sh.lua`

Officers impound a nearby vehicle; owners see an informational retrieval fee in the impound lot.

```lua
Impound.enabled     = true
Impound.fee         = 500     -- retrieval fee shown in the lot (USD) — informational/RP only, LACORE has no economy so nothing is charged automatically
Impound.maxDistance = 8.0     -- how close an officer must be to impound
Impound.persist     = true    -- remember impounded vehicles across restarts
```

## K9 — `configs/cfg-k9-sh.lua`

A trained police dog that heels, searches, engages and loads into the patrol car. It ignores ambient
stimuli (gunfire, panic) and holds its task — so it behaves like a working K9, not a wandering animal —
and it **shows on the map**.

```lua
K9.enabled        = true
K9.jobs           = { "Law Enforcement" }
K9.model          = "a_c_shepherd"   -- dog ped model
K9.name           = "Rex"
K9.followDistance = 1.6
K9.maxDistance    = 40.0             -- teleport back to heel if left this far behind (0 = never)
K9.searchRadius   = 12.0             -- radius the dog sweeps on /k9 search
K9.searchWalk     = 6.0              -- how far ahead it trots to sniff
K9.blip = { enabled = true, sprite = 442, color = 5, scale = 0.85 }  -- map blip
```

Commands, orders and the handler workflow are in the
[LEO Field Tools guide](/user-guide/leo-field-tools#-k9); every order is also a keybindable command
(all unbound by default).

## Mobile Fingerprint ID — `configs/cfg-fingerprint-sh.lua`

A handheld biometric scanner for LEO (like a mobile biometric ID scanner). `/mobileid` (bindable in *FiveM
Settings → Key Bindings*) scans the nearest **restrained** suspect and matches the print against the
records database — returning their identity (name, DOB, description, address, DL, and **active warrant /
BOLO** flags) even when they carry no ID and refuse to identify themselves.

```lua
Fingerprint.enabled       = true
Fingerprint.requireCuffed = true    -- only a cuffed suspect can be scanned (false = anyone in range)
Fingerprint.range         = 2.5     -- how close the suspect must be (metres)
Fingerprint.scanSeconds   = 2.2     -- capture animation length in the UI
Fingerprint.openKey       = ""      -- optional default key for /mobileid (players can bind it themselves)

-- Prints are something you TAKE: an officer enrols a restrained suspect from the
-- device, and that register is what a crime-scene print is matched against.
Fingerprint.Register = {
    required     = false,          -- true = a scan only identifies people whose prints are on file
    evidenceType = "fingerprint",  -- evidence type used when a latent is matched
}

-- /liftprint [incident] — lift a print off the nearest vehicle.
Fingerprint.Latents = {
    range             = 4.0,   -- how close to the vehicle (metres)
    touchesPerVehicle = 4,     -- recent occupants a vehicle remembers
    touchKeepMinutes  = 60,    -- older than this is not usable evidence
    keepMinutes       = 120,   -- how long an unmatched latent stays listed
}
```

The full lift → run → enrol → match workflow (with what players see at each step) is in the
[LEO Field Tools guide](/user-guide/leo-field-tools#-fingerprint-scanner--latent-prints). Who left a
print is not guessed: the client reports the plate when a player gets into a vehicle, so a latent
resolves to the people who actually sat in that car recently — old touches expire, the list is
capped per vehicle, and your own touch is excluded.

<Callout type="info">
  **`Register.required` ships off.** With it off, a scan identifies from the records profile exactly as
  before and only *reports* whether prints are on file — so nothing changes for an existing server.
  Turning it on makes the register mandatory for identification, which is the stricter, more
  investigative setup, but it means nobody can be identified until they have been printed. Your call.
</Callout>

<Callout type="info">
  **Fair play** — you can only scan a **cuffed** suspect who's close by, so there's no remote ID of free /
  running players; detain them first. Every scan is written to the [Big Brother](/features/security#activity-log-big-brother)
  audit log. Turn the whole feature off with the `fingerprint` [feature toggle](/configuration/features).
</Callout>

## Global-ban network — `configs/cfg-globalban-sh.lua`

A shared ban list, **managed centrally by the LACORE team**: your server **reads** the network list and
refuses any identifier banned on it. There is nothing to obtain or configure to participate in reads.

| Setting | Default | Meaning |
| --- | --- | --- |
| `GlobalBan.enabled` | `true` | Check joining players against the shared list. |
| `GlobalBan.refreshMinutes` | `15` | How often the list is refreshed. |
| `GlobalBan.checkTypes` | license/discord/… | Which identifier types are matched. |
| `GlobalBan.failOpen` | `true` | If the list can't be reached, **let players in** (never lock out your server on a network hiccup). |
| `GlobalBan.propagate` | `false` | Inert for normal servers — **writing** to the network is reserved for the LACORE team (needs a central credential you can't obtain). Leave it off; your server only reads. |

<Callout type="warning">
  `failOpen = true` is the safe default — a network outage should never stop legitimate players from
  joining. Only set it `false` if you'd rather refuse joins than risk letting a networked-banned player in.
</Callout>

## Model library — `configs/cfg-library-sh.lua`

The dashboard's model library shows what **your** server has. `/modelscan` finds and measures the
models, `/modelcapture` photographs them.

<Callout type="info">
  You do not have to configure anything. Leave `uploadUrl` empty and LACORE hosts the pictures for
  you: your server asks for a short-lived upload session with its licence key, the screenshots go to
  LACORE's image host, and the dashboard shows them.
</Callout>

| Setting | Default | Description |
| --- | --- | --- |
| `Library.uploadUrl` | `""` | Your own upload endpoint. Anything screenshot-basic can post to: it sends multipart form data and must get JSON back containing a URL. Discord webhooks work (the response carries `attachments[1].url`), as does any uploader answering `{ "url": "https://…" }`. |
| `Library.imageHosts` | `{}` | Only needed when your uploader answers with a URL on a *different* CDN domain than it accepts uploads on. The server otherwise only accepts image URLs whose host matches where the run is actually uploading, so a misbehaving client can never inject a foreign image into your dashboard. |
| `Library.settleTime` | `0.8` | Seconds to let a model settle before the photo is taken. |
| `Library.maxPerRun` | `150` | Models processed per `/modelcapture` run. |

<Callout type="warning">
  `uploadUrl` is deliberately **not** remotely editable. Where your data goes must never be something
  the dashboard can change — the same reason `PhoneCfg.cameraUpload` is refused by the remote-config
  allowlist. Edit it in the file, or nowhere.
</Callout>

## Replay & Director's Cut — `configs/cfg-replay-sh.lua`

Records what happens around a player into a compact binary clip (`.lcr`) that can be played back
later — the raw material for cinematic shots, trailers and highlight videos. A content-creation tool,
**not** an admin evidence tool (that is the [Big Brother log](/configuration/security)).

`/replay start` samples nearby players and their vehicles into memory; `stop` ends the take, `save
[name]` encodes and uploads it, `discard` throws it away, and `list` / `play` / `delete` do what they
say. Clips live on the **server** (`data/replays/<license>/`) because a FiveM client cannot write
files — which is why the quotas below exist: clips cost your disk. `/replay play <id>` rebuilds the
scene out of ghost entities only the viewer can see.

<Callout type="warning">
  FiveM cannot encode video. A director's cut sets up the **shot** — scene, camera, timing — and you
  record it with OBS or ShadowPlay like any other gameplay. There is no MP4 coming out of this.
</Callout>

| Setting | Default | Description |
| --- | --- | --- |
| `Replay.enabled` | `true` | Master switch. Also gated by `Features.replay` — either one off disables the whole thing (no commands, no loops, ~0 ms). |
| `Replay.command` | `"replay"` | The command. Renaming it renames the `/help` suggestions too. |
| `Replay.debug` | `false` | Verbose logging to the server console and F8. Worth turning on when a clip won't save or plays with pieces missing — those failures are quiet by nature. `/replay debug` flips it at runtime. |
| `Replay.sampleHz` | `10` | Samples per second. Playback interpolates, so above ~15 buys almost nothing visually while making clips proportionally bigger; below ~6 fast vehicles start to look like they teleport. Hard range 1–30. |
| `Replay.radius` | `50.0` | How far from the recorder an entity is picked up, in metres. Anything that walks out simply stops appearing (and reappears if it comes back). Bigger = more entities = bigger file. |
| `Replay.maxDurationSec` | `180` | Longest single take. |
| `Replay.maxEntities` | `32` | Most entities recorded in one take. |
| `Replay.animCandidates` | 4 entries | The animations the recorder watches for (hands up, hand on holster, cuffed, downed). FiveM has no native that asks a ped *which* animation it is playing — only whether it is playing a specific one — so a recorder can only spot poses it was told to look for. Anything unlisted still replays: the ghost falls back to walk/run/idle from how fast it is moving. |
| `Replay.grades` | 5 entries | How each colour grade in the "Look" tab is achieved. `tint` / `tintAlpha` is a coloured sheet drawn over the game — always works, but can never *remove* colour. `modifier` / `strength` is a GTA timecycle, the only way to desaturate or crush contrast — but it is addressed by asset name, and an unknown name silently does nothing. If `noir` doesn't come out monochrome on your build, try another `phone_cam` number. |
| `Replay.dofNear` / `dofFar` | `0.45` / `1.9` | Depth-of-field band, as a multiple of the focus distance. |
| `Replay.dofStrength` | `1.0` | Depth-of-field strength. |
| `Replay.maxClipsPerPlayer` | `20` | Per-player clip count quota. |
| `Replay.maxTotalBytesPerPlayer` | `20 MB` | Per-player disk quota. |
| `Replay.saveCooldownSec` | `20` | Minimum gap between two saves. |
| `Replay.chunkBytes` | `48 KB` | Upload chunk size. |
| `Replay.uploadTimeoutSec` | `60` | Upload timeout. |

## Bug reports — `configs/cfg-report-sh.lua`

`/lacorereport` opens a small form any player can use to report a bug **in LACORE itself**. It goes
to the LACORE team's dashboard over the same relay this resource already uses for telemetry — not
into your database. It is not a replacement for your own `/report` (reporting a *player*) or your
support tickets.

| Setting | Default | Description |
| --- | --- | --- |
| `Report.enabled` | `true` | Master switch. Also gated by `Features.bugreport` — either off disables it. |
| `Report.command` | `"lacorereport"` | The command. Renaming it also renames the `/help` suggestion and the cooldown message. |
| `Report.cooldownSec` | `120` | Wait between two reports. Enforced on the **server**; the client only mirrors it for the countdown, so a modified client cannot bypass it. |
| `Report.maxLength` | `800` | Longest report a player can type. The server enforces the same cap again — a report is a payload from a client, and the client is never the only gate. |
| `Report.categories` | 5 entries | The category dropdown: Bug, Exploit, Translation, Suggestion, Other. Purely a UI label; nothing branches on it, so rename freely. |

Set `Webhooks.BugReport` in [`cfg-server-sv.lua`](/configuration/discord) to get your own copy in
Discord as well — local output is never replaced, only added to.

## Smaller files

| File | What it holds |
| --- | --- |
| `json/emojis.json` | The `:shortcode:` → emoji map used in chat / MDT text. Plain JSON — add your own entries. (Was `configs/cfg-emojis-sh.lua` before 3.4.3.) |
| `configs/locale-sh.lua` | Registers the active `Locale` table from `Language` (and `MdtLanguage`). To add a language, translate `lang/en.*` and register the code here. |

<Callout type="info">
  These files rarely need editing. Emoji shortcodes and language registration are the only reasons to
  open them.
</Callout>
