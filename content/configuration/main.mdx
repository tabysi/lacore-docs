# Main Config — `config.lua`

The central gameplay/world config. Escrow-ignored — edit freely.

<Callout type="info">
  Since 3.4.4 `config.lua` holds only the core settings below. The data tables it used to carry
  moved into their own files (backward compatible — an old `config.lua` that still defines them
  wins): `agencies` → `cfg-agencies-sh.lua`, `BusStops`/`BusRoutes` → `cfg-busroutes-cl.lua`,
  `textEntries` → `cfg-gametext-cl.lua`, `customIcon` → `cfg-phoneicons-cl.lua`,
  `indestructibleProps` → `cfg-props-cl.lua`, `initialAOPs` → `cfg-server-sv.lua`.
</Callout>

## General settings

| Setting | Default | Description |
| --- | --- | --- |
| `trainsEnabled` | `true` | Enable metro trains (only metros by default — others can bug out). |
| `ThirdEye` | `true` | Enable ox_target player interactions (cuff / drag / put-in-vehicle / medic / revive / carry …). Requires `ox_target`. Chat commands (`/release`, `/uncuff` …) stay available regardless. |
| `GameMinuteSeconds` | `8` | Real seconds per in-game minute. `8` → a full day ≈ 3.2 real hours. `60` = real time (1:1). |
| `SyncGameTime` | `false` | `true` = LACORE owns the world clock so it advances smoothly for everyone and `/time <hh> <mm>` works. Ships `false` so a time/weather resource you already run is never fought over the clock — turn it on if LACORE should control time. |
| `Language` | `"en"` | Locale for all server/HUD Lua text. Supported: `en`, `de`, `ru`. |
| `MdtLanguage` | `""` | Separate language for the NUI (MDT / Dispatch / Profile). Empty = follow `Language`. |
| `UseDatabase` | `true` | Mirror every persistent store to MySQL (oxmysql). `false` = local JSON only. |
| `DispatchMapStyle` | `"styleGrid"` | Dispatch map tile style: `styleAtlas`, `styleGrid`, or `styleSatelite`. |
| `ShowIncidentBlips` | `false` | Show a GTA map blip for every active incident to on-duty units. |
| `DispatchTileBase` | `""` | Override the map-tile source (leave empty for the `lacore-maps` resource). |
| `CallRetentionDays` | `7` | Days resolved dispatch incidents are kept before pruning. Active incidents are always kept. |

## Call Center (911 / 311)

The `CallCenter` table configures the incoming call queue:

```lua
CallCenter = {
    Enabled          = true,   -- master switch for the 911/311 system
    UseVoice         = true,   -- connect caller ↔ dispatcher via pma-voice
    VoiceChannelBase = 1000,   -- first of 100 voice channels used for sessions
    AutoIncident     = true,   -- auto-create an MDT incident when no dispatcher is online
    MaxCallLogs      = 500,    -- archived calls kept in data/call_logs.json
    MaxLogResults    = 100,    -- max results per dispatcher log query
    AllowCommands    = true,   -- allow /911 and /311 chat commands
    Debug            = true,   -- verbose 911/311 flow prints (set false in production)
}
```

<Callout type="warning">
  `VoiceChannelBase` occupies 100 channels (`base … base+99`). Make sure that range doesn't collide
  with other pma-voice usage.
</Callout>

## Agencies (`cfg-agencies-sh.lua`)

`agencies` is the master list of departments used across the CAD/MDT — since 3.4.4 in its own
file, `configs/cfg-agencies-sh.lua`. Each entry defines the department shown on duty and its
loadout:

```lua
agencies = {
  {
    type = "Law Enforcement",           -- duty-window group (see below)
    short = "LAPD",
    cad = "lapd",                       -- which CAD/MDT /mdt opens (see below)
    long = "Los Angeles Police Department",
    motto = "To Protect and Serve",
    cad   = "lapd",                     -- which CAD design this agency opens
    equipment = {
      { weapon = "WEAPON_SERVICEPISTOL", components = { "COMPONENT_AT_PI_FLSH" } },
      { weapon = "WEAPON_TASER7", tint = 1 },
      { weapon = "WEAPON_DD11_B", rack = "rifle", components = { ... } },
      -- …
    },
    wallpaper = { "hacking_pc_desktop_3", "hacking_pc_desktop_3" },
  },
  -- … many more
}
```

### Fields

| Field | Required | Description |
| --- | --- | --- |
| `type` | yes | The kind of department — see the table below. Decides the role, not the look. |
| `short` | yes | What players type: `/onduty LAPD 1A-12`. Also what the CAD shows as the department. |
| `long` | yes | Full name, shown in the MDT header and in the on-duty message. |
| `motto` | no | One line under the name in the MDT. `""` for none. |
| `cad` | no | **Which CAD/MDT design this agency opens** — see [Choosing the CAD design](#choosing-the-cad-design). |
| `equipment` | no | Loadout handed out on duty. Supports `components`, `tint`, and `rack` (weapon goes in the vehicle rack instead of the officer's hands). |
| `wallpaper` | no | `{ in-car screen, MDT background }` — texture names or an RGB triple. |
| `primary` / `secondary` | no | MDT accent colours as `{ r, g, b }`. |

The `type` field controls the role a member gets and how dispatch treats them:

| `type` | Role |
| --- | --- |
| `Law Enforcement` | Full LEO: CAD, calls, units, queries, charges. |
| `Fire/EMS` | Fire / medical units in the EMS CAD. |
| `Coroner` | Coroner tools. |
| `Tow Truck` | Tow contacts (the only type any player may go on duty as without membership). |
| `Private Security` | CCTV `security` access + limited tools. |
| `Animal Control` / `Public Works` | Utility departments. |

### `cad` — the terminal a department opens (since 3.4.9.2)

Without a `cad` field LACORE guesses the terminal from the department name: a `short` containing
`lapd` gets the LACORE Mobile Client, `lasd`/`sheriff`/`bcso` the LASD CAD/PCMS, any other Law
Enforcement department the Agency MDT, and Fire/EMS/Coroner the EMS CAD. Set `cad` on an entry to
decide it yourself — the explicit value always wins over the guess **and** over the `type`:

| `cad` | Terminal |
| --- | --- |
| `"lapd"` | LACORE Mobile Client (LAPD PremierOne look) |
| `"lasd"` | LASD CAD/PCMS terminal |
| `"agency"` | Agency MDT (CHP style) — the all-round LEO terminal |
| `"ems"` | EMS / Fire CAD |
| `"90s"` | 9100-T retro terminal |
| `"penn"` | Pennsylvania CAD (add-on; falls back to the Agency MDT when the add-on is not unlocked) |
| `"none"` | this department gets no terminal at all |

Aliases are accepted (`"pcms"` → `lasd`, `"chp"` → `agency`, `"fire"` → `ems`, `"retro"` → `90s`,
`"off"` → `none`, …). An unknown value prints a console warning and falls back to the automatic
routing, as does leaving the field out.

`equipment` entries support `components`, `tint`, and `rack` (weapon on a station rack). `wallpaper`
is the MDT background (texture names or an RGB triple).

<Callout type="info">
  The three shipped sheriff's offices — **VCSO**, **RSO** and **SBCSD** — carry `cad = "lasd"` and
  open the Sheriff CAD; their names say nothing about a terminal, so the automatic guess would put
  them on the Agency MDT. Remove the line to put one of them back.
</Callout>

## The other data lists (own files since 3.4.4)

| List | File | Purpose |
| --- | --- | --- |
| `textEntries` | `cfg-gametext-cl.lua` | Custom GTA text labels (advertisement titles, session messages, restriction notices). |
| `customIcon` | `cfg-phoneicons-cl.lua` | Phone/contact icons (name → Discord-style handle + GTA icon). |
| `BusStops` / `BusRoutes` | `cfg-busroutes-cl.lua` | Public transit stops and routes. |
| `initialAOPs` | `cfg-server-sv.lua` | Starting Areas of Patrol for the AOP voting system. |
| `indestructibleProps` | `cfg-props-cl.lua` | Props made indestructible (traffic signs, hydrants, streetlights …). |

`RegisterPrices` and `SpeedLimits` were removed in 3.4.4 — nothing in the code ever read them.

<Callout type="info">
  Coordinates in these lists are placeholders tuned for a specific map — adjust them to your server.
</Callout>
